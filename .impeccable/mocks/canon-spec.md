# 「标准写法」全量原型 · 施工规格

> **这份规格的来历（原型 → 决定 → 实现 的指针）**
>
> 本仓的原型不是一次性草稿，而是**有契约、有门禁、有决策留档**的体系。三段互指如下：
>
> 1. **原型（本目录）**：31 页浅色 + 31 页深色副本（`pages/*.html`，画廊入口 `pages/index.html`），
>    视觉系统单源 `pages/canon.css`，本规格是它的施工条文。
> 2. **决策留档**：`.impeccable/mocks/decision/` 存着方向轮的六个候选世界（canon / assigned /
>    challenger-* 浅深两版）与 `pages/direction.html`——「标准写法」就是那一轮用户拍板的。
>    另有 10 个 `prototype-*.html` 在 `prototype/p5-p6-2026-10-11` 与
>    `prototype/p9-p18-2026-10-17` 两个分支上，住在各自要原型的路由旁边。
> 3. **实现侧**：决定折回在仓库根的 `DESIGN.md`（令牌层 + 八节正文）与
>    `src/app/theme/brand.ts`（色值单源）；深色升为一等外观的裁定见
>    `docs/adr/0006-dark-mode-first-class.md`。
>
> ⚠ **本目录是契约源，不是草稿**：`canon.css` 被 `src/app/theme/brand.spec.ts`（`pnpm verify` 的单测）
> 与 `globals.css` / `brand.ts` / `app-shell.tsx` 的令牌链引用，**不许搬去一次性分支**。
> 这与通用原型惯例「原型离主干、主分支只留决定」不同——本仓把原型升格为契约源留在主干，
> 理由与依赖方见 `.trellis/spec/frontend/prototype-guidelines.md` 的「为什么留主干」一节。

视觉系统在 `canon.css`，骨架模板看 `workbench.html`（照抄它的 nav + 顶栏 + .page 结构）。
旧世界（案卷脊标）的对应页面在 `../_archive-world-jibiao/`，**功能与内容从那里搬**，视觉全部换成 canon.css 的类。

## 弹层（表单类页面共用）

`canon.css` 有一层弹层件，**新页要用就照 `matter-create.html`**：

- `.mask` 遮罩（fixed 铺满、居中）＋ `.modal`（默认 780，`.narrow` 520 / `.wide` 900，`max-height:86vh`）；
- `.modal-h`（标题 + `.x` 关闭）／`.modal-b`（可滚动体）／`.modal-f`（底栏，`.sp` 顶开，左取消右主操作）；
- ⚠ **一个页面只放一个 `.mask`**：两个都是 fixed，会叠在一起。成功态那类「另一屏」另开一页
  （样板：`matter-created.html`），关闭/「再建一条」用链接回表单页。

表单体在 `.modal-b` 里分三段用：

1. `.fsec` 分区标题（「基本信息」「当事人」「办理与关注」「其他」）；
2. `.fgrid` 12 列网格，每格 `.field` 加 `.spanN`。**每行最多两个字段**：常规一律 `span6`
   （一整行才用 `span12`），**不要用 span4 拼三格一行**——780 宽的弹层里三格会挤成十几个字宽；
   `.spanN` 已定义 2/3/4/5/6/7/8/9/10/12，别写没定义的档位（会退化成 1 列宽）；
3. `.pcard` 当事人块（一块一个当事人：`.pcard-h` 写「当事人 N」+ 右侧删，内部仍走 `.fgrid`，
   名称整行、类型与诉讼地位各半行）。

`.field>label` 的必填星号写 `<b>*</b>`（红）；提示语用 `.hint` / `.hint.warn` / `.hint.err`
（落点②「字段说明」，不铺成卡片里的一行散文）。

**弹层比视口高是常态**（案件表单 4 区就 1264px）：`.modal-b` 自己滚，头与底栏钉住不动。

**字段顺序按逻辑配对**（案件样板）：案名 → 案由/类型 → 我方地位/程序 → 法院/案号 →
立案日期/来源事项 → 标的额/风险等级 → 当事人 → 办理与关注 → 基本情况。配对原则是
「同一组事实挨着」，不是按 schema 字段声明序照抄。

## 全局纪律

1. **画布 1440 宽**（由 canon.css 的 `html,body{width:1440px}` 定）；纵向可滚动，页高不限，`overflow` 不裁剪。**只画浅色**：深色版由脚本复制文件 + 给 `<body>` 加 `class="dark"` 生成，所以**不要写死任何颜色**，一律用 canon.css 的变量与类。
2. 单文件、`<link rel="stylesheet" href="canon.css">`、**无 JavaScript**、不引任何外部资源（无 Google Fonts、无图片）。需要图形一律用 CSS 画（点、条、色块）。
   - 需要「点一下开层 / 切换」时用纯 CSS 的 `:target`（样板：细项页的 `#form` 弹层、角色权限页的主从切换），**不要引脚本**。
3. 只允许 canon.css 里的类。确需一次性布局（列宽、卡片间距）时，可用行内 `style` 写 `width`/`margin`/`display:grid`，**不得用来上色或加装饰**（唯一例外：`.swatch` 的 `background` 是数据本身）。
4. **标题层级不跳级**：顶栏页名 `h1` → 页面主区块的卡片头 `h2` → 嵌套区块 `h3`。
   `.card-h` 对 h2/h3 同貌（14px/600），所以改标签不动视觉。新增页面后跑
   `agent-work/_chk/check-headings.mjs`（`h1` 后直接 `h3` 是历史缺陷，已全站修过一轮）。
5. 骨架：`<nav class="nav">` 三组八项（概要：工作台；业务：案件 / 事项 / 当事人 / 已归档；系统：功能配置 / 用户管理 / 角色权限）＋ `navfoot`（`系统管理员 · 全局管理` + `modesw`）＋ `topbar`（`h1` 只写当前页名）＋ `.page`。当前页的导航项加 `class="it on"`。

   > **通知入口同样已从主导航迁出（2026-10-19），原型未跟**：通知不是模块而是**收件箱**，
   > 所以它不做成一个 `.it`（`.it` 的语言是"跳到某个区块"，整行铺满、左对齐），
   > 而是落在 `navfoot` 里、与身份卡**同一行**的一枚 `.inbox`：只有铃铛 + 未读徽标
   > （antd `Badge`，未读为 0 时不出），未读数不在行内另占位置——侧栏只有 191px，
   > 字要让位给右边那张身份卡；"这是什么"改由 `aria-label` / `title` / `Tooltip` 三处承担，
   > 有未读时三处都带条数（色不作唯一通道）。当前页加 `.inbox.on`。
   > 整行是 flex `space-between`，两枚胶囊等高（34px）。
   > 理由与身份卡那条同源——底缘这一簇是"我的"（通知 / 头像 / 菜单 / 退出），不是模块导航。

   > **底栏身份区在实现侧已演进（2026-10-18），原型未跟**：原型是「一行姓名 + `modesw` 两个文字档」，
   > 落地为**头像 + 昵称的一枚按钮**（antd `Avatar` + 名字），点开是一份右侧菜单——
   > 菜单里是「个人设置 / 系统颜色（三枚图标：跟随系统·浅色·深色）/ 我关注的 / 退出登录」。
   > 三档的选中态表达**偏好**而不是当前深浅（`system` 档下这两者不同）。
   > 原型仍是**视觉令牌与页面构图**的权威来源，但这一处骨架以上面的实现为准：
   > 原型禁 JS，画不出一枚"点开有菜单"的控件，只能停在静态文本。
   > 见 `docs/adr/0006-dark-mode-first-class.md` 的"追加"一节。
6. **文案禁旁白**：每句要么是事实、要么是动作；不写「这里显示…」「用于…」「本页…」。空态＝事实 + 动作（如「暂无数据」＋「新增」）。
7. **颜色不作唯一通道**：期限与状态永远「点径 + 词」（`.pill over` = 逾期，`.pill due` = 临期，`.pill ok` = 达成，`.pill gray` = 中性）。
8. 表格一律 `<colgroup>` 定列宽，可伸缩列加 `class="ellip"`；**列宽合计 ≤ 1100**。数字列加 `class="num"`（右对齐用 `class="r"`）。
9. 真实数据：案号 `AJ-YYYYMMDD-NNN`（案件）/ `SX-YYYYMMDD-NNN`（事项）；案名格式「公司简称 案由」；公司名与节点名照 `workbench.html`，需要的可按同一风格补。
10. 每页都要有**真实数据行**（不许 3 行占位）与**至少一处边界呈现**（从旧页搬：不可见行降级 / 材料缺失 / 已并入 / 已撤销 / 权限仅可见本部门 之类）。
11. **对比度是令牌的下限，不是事后补的**：三档墨色与语义色都钉在 WCAG AA 正文线 4.5:1 之上，且要在**最差的浅色面**（纸色 `#F5F6F8`）上仍有余量。改任何色之前先跑 `agent-work/_chk/token-contrast.mjs`（令牌配对）与 `agent-work/_chk/contrast-all.mjs`（全站渲染实测），别凭肉眼。已知坑：① `.gl`/`.ph` 这类弱级文字曾经是 `#9CA3AF`（2.54:1）；② 语义 tag 的浅底会把前景压到 4.3 上下，故 `.tag.green/red/amber` 的底用 `var(--card)`。
