## 现行八条禁令（逐字取自技术选型 §13.5；**不要抄 §12.3 的 v4 版**）

1. **`src/shared/**` 只放纯 TS**：不得 import `next/*`、`react`、Node API——它同时被客户端与服务端引用，污染了就会把服务端代码带进前端 bundle，CI 必须拦得住。
2. **Drizzle partial index 的 `.where()` 只用 `sql` 模板，禁用 `eq()/and()`**（0.45.3 实测生成非法 `$1`，open issue #4790）；锁 `drizzle-orm`/`drizzle-kit` 精确版本，升级时复验。
3. **生成列写法**：`generatedAlwaysAs(sql\`…\`)` 或回调形式，**pg 侧没有 `.stored()`**；PG 只有 STORED，生成列不可进 PK/FK/unique、不可引用其他生成列。
4. **schema 演进只用 `generate` + `migrate`，开发期也不用 `push`**：`push` 检测不到已有索引 `.where()`/表达式变化，而软删 partial unique 是权限模型骨架，用 push 会出现"代码改了、库没改、CI 还绿"的静默漂移。
5. **业务读写一律 `/api/**` Route Handler**，且**鉴权必须在每个 handler 内部 `withScope()`**——Next 官方明令不得只依赖 proxy/middleware（matcher 排除路径会连带跳过该路径上的 Server Function）。Server Function 只做编排，不承载第二套权限判断。返回体一律 JSON，不可见资源 **404**。
6. **页面壳不得预取业务数据**：SSR 只出外壳与静态文案，一切业务读取发生在鉴权后的 `/api/**`。否则行级数据范围被页面壳绕开。（替代原"整站 SPA"那条。）
7. **前端只允许一套组件体系：Ant Design 6 + Tailwind v4（只管容器布局）。**（v6 改判，现行文字见技术选型 §13.6.2。）三个机器可拦的子条款：不得引入第二套体系或第二家叶子库（`radix-ui`/`class-variance-authority`/`@ant-design/pro-components`/`lucide-react`/`react-hook-form`/`date-fns`）；不得走 antd 深路径（一律顶层 `"antd"`，类型用 `TableColumnsType`/`FormRule`）；色值只在 `src/app/theme/brand.ts` 定义。清单里没有的件一律自封装进 `components/ui/`（现状只剩 FileUpload 的预签名直传那段）。
8. **表格一律经 `components/ui/data-table/DataTable.tsx` 封装并强制服务端分页/排序/筛选**（每页上限 100）——理由不是性能而是权限：客户端全量拉取再本地筛等于绕过 `ScopeResolver`（权限草案 §4）。表单**只用 antd `Form`**（v6 改判，§13.6.2），规则从 `shared/schema` 的 Zod 经 `components/form/zod-rules.ts` 推导；日期库全项目只允许 `dayjs`；组件内不得自带第二套校验规则。

外加两条部署级：**(a)** 多副本必须共配 `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` 与 `deploymentId`，且不使用 `'use cache'`/跨实例共享缓存；**(b)** worker 与 app 都要处理 SIGTERM，留 10–30s drain，outbox 投递不得在关闭时被掐断。

**落点分布**：① 在 [Directory Structure](./directory-structure.md)（依赖方向）；②–④ 在 [Database Guidelines](./database-guidelines.md)；⑤ 在 [Error Handling](./error-handling.md)；⑥⑦⑧ 在前端目录（该三份为**摘编**，全文以本节为准）；(a)(b) 在 `deploy/` 与 `worker/`。

## CI 必须拦得住的东西（人工审不算拦）

| 检查 | 判据 |
|---|---|
| 裸表访问 | 宿主表读取未经 `ScopedQuery` 构造 → 失败（权限草案 §4 防漏机制 1：仓储基类断言 + lint） |
| `shared/` 污染 | `src/shared/**` 出现 `next/*`/`react`/`node:*` import → 失败 |
| CHECK↔值数组一致性 | 迁移 SQL 的 `CHECK` 取值与 `src/shared/enums` 值数组集合比较，不等 → 失败 |
| 同构表列集合 diff | `matter_*` 与 `risk_matter_*` 列集合差异非空 → 失败 |
| `scope_key` 归一化 | 枚举表 §4.4 的 8 条必过向量逐条断言 |
| 转案件原子性 | 注入一次失败，整体回滚（矩阵 §4） |
| 鉴权漏挂 | `/api/**` handler 无 `withScope()`（或显式白名单：配置 5 表、登录入口） → 失败 |
| lint / typecheck / test | `pnpm lint && pnpm typecheck && pnpm test` 全绿 |

## 验收门禁（什么时候算"做完"）

- **权限矩阵**：权限草案 §10（5 角色 × 3 对象 × 7 入口）+ 4 条归属/选人用例，参数化生成，**任一红即不通过**（落地方案 §5）。

### 注释里承诺断言时，必须写出**能被 grep 到的标识**（2026-10-18）

**规则**：注释/文档里说"这件事由某条断言守着"时，只能指向**具体的文件 + 测试名
（describe/it 名）**，且那个标识要能用 `grep` 直接命中。**不许**写"某脚本里有""冒烟里有一份"
这类说法。

**为什么**：`scope/visibility.ts` / `scope/visibility.spec.ts` / `services/notifications.ts`
三处注释曾一致地写着「真库矩阵断言在 `agent-work/smoke-notifications.mjs` 里」——
**那份断言从来不存在**（`grep canSeeHostFrom` 该文件零命中）。三处互相印证，读起来像已经验过了，
于是 MATT-76 交付时那一层实际是**空的**，而没有任何门禁会红。
根因不是笔误：**散文式引用没人能核**，它能一直错下去；可 grep 的标识能当场证伪。

**配套（同一件事的另一半）**：写进注释的断言还得**真的能落地**。上面那份之所以从没实现，
是因为它被安置在冒烟里，而冒烟只走 HTTP、够不着内部函数。落不了地时只有两条路：
换个能落地的位置（那次改成了 `visibility.spec.ts` 的「② SQL 形态」——真调 `visibility()`、
读它实际产出的谓词），或者把话说清楚它**没**被守着。
**"落不了地"不是把承诺留在原处的理由。**

⚠ 这一条是**判断题、不是机械检查**：没法机械判断"这句话承诺的断言存在吗"。
能机械化的部分已经机械化了（见 lint-guard 的源码断言各条）。

### 注入/还原一律走备份，**不用 `git checkout <file>`**（2026-10-18）

**规则**：往源码里注入缺陷（反向红、临时探针）之前先 `cp` 一份备份，还原时 `cp` 回来。
**不许**用 `git checkout <file>` / `git restore <file>` 还原。

**为什么**：本仓工作树**常年带着别条线的未提交在制品**，而 `git checkout <file>`
是「把该文件退回 HEAD」—— 它**同时抹掉别人的改动**，而现场**看不出来**：
你只会发现**自己的**改动没了（因为你正在找它），别人的那句注释删除/列宽调整是**静默消失**的。

**实测事故（2026-10-18）**：做反向红时用 `git checkout src/app/lib/server/services/reports.ts`
还原注入，把品牌线那处「删掉一句注释」一起抹了。约 40 分钟后才发现 ——
当时以为只丢了自己的改动。找回靠 `git fsck --no-reflogs --unreachable` 捞出
103 个不可达 blob、从中认出原版本；**`git gc` 一跑就真没了**。
（那条路径本身已于 2026-10-24 删除，见 `docs/adr/0008`。事故的**教训与文件是否还在无关**，
原文一字未改，只补这一句 —— 免得下一个人去 `ls` 一个不存在的路径。）

**这条规矩仓里早就写着**，但只写在 5 个 `agent-work/revred-*.mjs` 的**头注**里
（「还原一律用 `restore`，不要用 `git checkout`」）—— 手搓的临时注入脚本不读那些头注，
所以它一直没生效。写在这里是为了让**临时脚本的作者**也读到。

**配套**：`revred-*.mjs` 自己实现 `.bak` 备份 + `restore` 子命令，形状可抄；
临时探针同理，别图省事。

**手搓探针的备份名必须带上「探针名」，还原时不许用通配符**（2026-10-18 补）。
`revred-*.mjs` 的备份名是 `${file}.revred-<工具>.bak` —— 那个工具名不是装饰，
它就是防这件事的。

**实测事故（2026-10-18）**：同一轮里对同一个文件跑了好几个手搓探针，
备份都写 `/tmp/watch.bak` 这类**同名**文件；最后一次探针的备份捕获到的其实是
**上一次探针留下的注入态**。于是「还原」把上一个探针的注入又装了回去，
`watch.ts` 带着 `return true;` 躺在工作树里 —— **差一步就被提交**
（`git diff` 看得见，但那时我在看别的文件）。**症状与「实现有缺陷」完全同形**。

三条防线，缺一不可：
- 备份名带探针名（`/tmp/probe-watch-6133.bak`），**一个探针一个名字**；
- 还原后**必须** `git diff <file>` 确认干净，别只看「已还原」的打印；
- 别用 `cp /tmp/*.bak` 这种通配还原 —— 它会按字母序把**多个**快照依次盖上去。

### 反向红：注入之后先过**编译门**，再跑冒烟（2026-10-18）

**规则**：注入缺陷之后、跑冒烟之前，先 `node agent-work/revred-gate.mjs`。
它跑 `tsc --noEmit`，退出码非 0 就**不要**把冒烟的红记成「断言抓住了缺陷」。

**为什么**：注入写坏了（语法错、名字解析不到）⇒ 模块编译不出来 ⇒ **每条路由返 500** ⇒
冒烟红成一片 ⇒ 你以为验过了。**这是假红**，比假绿更难发现：假绿你会去查，
假红你会直接记一笔「验过了」。自动循环（`agent-work/_revred-loop.ps1` 那类）只数 `red=N`，
完全看不出来。

**本仓此前把机制记反了，这里是更正。** 四处（`revred-staff` / `revred-watch` /
`revred-batch` 的头注 + 两份 retro）写着「编译失败时 dev server 继续发旧产物，
冒烟会**假绿**」。2026-10-18 在真 dev server（`:3777`）+ 真库上实测三种注入形态：

| 注入形态 | `tsc` | 冒烟 |
|---|---|---|
| `visibility-gate` 原样（带 `void row;`） | 干净 | 30/3，三条都是断言红 |
| 同上但删掉 `void row;`（TS6133） | **红** | 30/3，**一字不差的三条断言红** |
| `return (true;`（语法错） | 红 | 每条路由 **500** |

Turbopack **不做类型检查**、只剥类型，所以类型错既不停摆 dev server、也不让它发旧产物。
`revred-staff` 那次「编译红 + 28/0 全绿」里的绿，同一段注释往下两行就写着
「修成可编译之后**仍然全绿**」——原因是那个 `findUnassignable` 调用**本来就冗余**
（该模式随后被删，见 `matters.ts` 门 4），与编译红没有因果关系。
**两件各自为真的事，被接成了一条假因果。**

**抓不到什么**：语义。注入写对了、但锚点落在无关的地方，编译一样干净、门照样放行，
红的不是你要验的那条断言。这道门只挡「红得不是地方」里**最便宜的一类**。

### 报「仓里没有 X」之前，先用**同一取法**验一次搜索（2026-10-18）

**规则**：任何"全仓只有 N 处 / 没有别的地方了"的结论，落笔前必须用**同一个命令**
搜一个**必然存在的正样本**，确认这条搜索真的能命中。

**为什么**：本机 `grep` 是 **ugrep**，`\d` 这类转义在裸形态下**静默不匹配** ——
返回 0 命中，而它其实是"搜不到"而不是"不存在"。两者在输出上完全同形。

**实测事故（2026-10-18）**：`grep -rn '\d{1,19}' src/` 返回 0，我据此向用户回报
「**零基线**，只有 `http.ts` 一处」，并把这个**假前提写进了子代理的简报**。
实际有 4 处 —— 子代理用 `-F` 反证了我：

```
① 裸 \d{1,19}      → 0 命中     ← 静默失配
② -F d{1,19}       → 1
③ -E '\d{1,19}'    → 2  ← 可用
④ -P '\d{1,19}'    → 2
```

**这与仓里的 canary 哲学同源**（「扫到 0 处是假通过」），只是发生在**代理自己的搜索**上、
而不是门禁代码里，所以一直没被记录。代价比门禁那次更大：**假前提会顺着简报流进下游**，
让子代理要么白干、要么花大量 token 反过来推翻你。
