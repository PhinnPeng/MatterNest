## 2. 背景与目标

**背景（基线 1.1 + 2026-10-10 改判 IQ-1/Q50）**：一家**企业**的法务团队（约 **10 人**）管理本企业卷入的诉讼与涉诉前风险。基线时代的"律所内部"口径作废（ADR 0001：企业是案件的当事方，不是替别人打官司的代理人）。风险事项与案件目前分散在台账与个人记录里，"风险 → 案件"的转化链路没有系统承载：转案件时字段靠手抄、期限靠记忆、关注人靠口头，结案后材料封存无人回收。MatterNest 以台账式管理为起点，把这条链做成一条有状态、有节点、有审计的生命周期。

**核心价值（IQ-2）**：**风险事项的记录与管理 + 案件的记录与管理 + 两者的转换**，三件套并列；M3/M4/M5/M7/M8 皆为其服务或附属（逐模块对齐时按"是否服务三件套"做减法）。

**目标（✅ 定稿，IQ-16 签字批准，2026-10-10；代拟过程见 `docs/PRD-phase1-g-targets-b5-draft.md`）**：基线全文没有可衡量目标。定稿四条 + 一条降级：

| # | 目标（定稿句） | 度量与达标线 |
|---|---|---|
| G1 | 上线 3 个月内，新发生的风险事项与诉讼案件 **100% 在系统登记**（不再回旧台账） | 台账抽对 + 登记计数；100% |
| ~~G2~~ | **KPI 撤销（用户裁"转案件不是强制的"）**。旧"完整率≥90% + 反绕过"口径作废——它与 IQ-3"被诉直建案是正当路径"自相矛盾 | 降级为 §6.1 **观测指标**：转案件链路使用率，无达标线。读法：若长期≈0，说明三件套的"转换"价值假设（IQ-2）未兑现——那是**复盘信号，不是考核**。链路正确性（转出案件必能在事项详情反查）属 F1-19/F2-22 功能验收，不占目标位 |
| G3 | 期限类节点提醒到达率 100%（一期仅 `in_app`：事件生成即到达）；开庭/举证类节点**超期未处理数 3 个月内环比降 50%** | `dedupe_key` 计数；节点超期行数趋势 |
| G4 | 归档案件的**材料完整率 ≥90%**（口径：归档动作时 `F2-26 归档完备性检查` 三项全过——①裁判文书类附件≥1 ②`closing_date` 已填 ③无待定未决节点；缺项强制归档记 reason 留痕，计入分母不计入分子） | 归档时点自动校验，数据源=`ARCHIVED.payload.missing_at_archive[]`（F2-26 新增） |

规模假设（待 SG-3 实数修正）：案件 30–80 件/年、事项 100–300 条/年、用户约 10 人。非功能底线五条（数据量/并发/留存/备份/部署）见 `docs/PRD-phase1-g-targets-b5-draft.md` 第一部分末表，其中部署形态行与 MATT-35 决策票联动。

## 3. 故事介绍

### 3.1 场景描述（一行一件事，来自基线功能地图 + 规格件）

```text
同事从云之家工作台点进应用，授权回调即完成登录，不必再记一个密码
运维留了一个本地密码账号兜底，云之家不可达时才用它进来
企业内有人离职，在职同步把他置为停用并当场吊销会话，他手里的案卷链接立刻 404
采购发现供应商有违约苗头，自助登记一条风险事项（FX-20260926-001），选风险等级"高"，顺手填了处理人与关注人
法务在产品里看到这条，把处理人改成自己——就是一次普通编辑，没有受理流程
经办人在事项下评论"已核查，先发函催告"；上报人在通知中心收到回音（关注列表里没有那条被动记录）
核查后对方起诉、法院立案，详情页点「转案件」，一次生成 2 个案件（AJ-…-001/-002）
被诉的案件不必先有条风险事项——直接新建，转案件只是入口之一
案件字段逐项补录：案由、程序（诉讼/仲裁/执行）、我方诉讼地位、标的额、受理机关、对方当事人
案件进入"进行中"，规则 3 生成举证/开庭/判决节点模板，提醒默认 {7,3,1} 天
开庭时间确认后填 end_time，判决节点时间未定就留"待定"
每周录进展，附件传传票与判决书，评论里 @ 协办讨论管辖异议
费用只记支出（诉讼费/律师费/保全费），详情页看得到按项目分组合计
开庭前 3 天系统给经办人和关注人发提醒，同一天多条提醒合并为一条
判决/调解书生效，经办人置"已结案"、补 closing_date；执行回款在原案补记，不自动归档
管理员启用规则 1 后，结案才自动归档
归档后列表默认隐藏，材料只读但评论与附件仍可追加，仅 full_admin 可撤销归档
经办人在"我的关注"看未读更新，点进去直接落到对应案件
被 @ 的人在通知中心看到评论摘要，点进去按当前权限渲染正文
同一供应商在两个案件里出现，当事人（对手方档案）页能看到"我可见的"关联案件
重复建档的"华为技术/华为技术有限公司"由经办发起合并，关联改挂主记录（F3-9）
助理只想看自己承办的，角色给 self_operator（L3）
IT 只管配置和账号，看不到别人的案卷（sys_admin 刻意压到 L3）
风控要撤销一次误归档，只能找持有 full_admin 的人
证件号在页面直接可见（能看案卷即能看传票），但批量导出默认脱敏、明文导出需特权并记审计
```

### 3.2 价值分析

| 功能 | 解决什么 | 支撑哪个目标 |
|---|---|---|
| 转案件（1:N + 可追加） | 现在手抄字段，关联一断就查不到源头 | 三件套之"转换"（G1 覆盖其登记面；使用率降为观测，G2 撤销后不再挂 KPI） |
| 业务自助登记 + 可选填处理人/关注人 | 风险源头在业务一线；报了没回音，下次就不进系统 | G1（IQ-5/IQ-13） |
| 状态配置驱动 + `semantics` 锚点 | 企业内习惯叫法不同，硬编码状态永远要改代码 | G1 |
| 5 触发 × 5 动作规则 + 同域唯一 | 提醒靠人记；规则放开成通用引擎会失控（一期只运维预置 9 条，IQ-9/16） | G3 |
| `last_progress_at` 与系统写入解耦 | "30 天无更新"被自动化自己刷掉，提醒永不触发 | G3 |
| `*_staff` 作权限主表 | 20 人规模没有部门，只能靠"我与这条记录的关系"分级 | G1（敢用才会填） |
| 当事人跨案共享 + 加密脱敏 | 同一对手在多个案卷里，重复录入且证件号裸存；对手画像（"这家第三次违约"）是风险识别输入（IQ-7） | G4 |
| 通知按 `dedupe_key` 聚合 | 一次转案件推 5 条，用户两周后就开始屏蔽通知 | G3 |

### 3.3 用户核心路径

```text
风险事项路径：登记（可选填处理人/关注人）→ 评论处置〔无预设节点，有硬期限才手动加节点〕→ 转案件(1:N) → 事项归档
案件路径：    转案件/**或被诉直接新建** → 进行中(P2 生成节点模板) → 节点推进+进展+费用 → 已结案(文书生效即置，执行作补记尾巴) → 已归档(终态)
横穿：        关注人=授权 → 通知/关注 feed → 明文导出(需特权，展示层全明文 IQ-12) → 撤销归档(仅 full_admin)
```

〔2026-10-10 IQ-3/IQ-5/IQ-6 注：转案件是建案入口**之一**非唯一——企业被诉常无对应事项，强制补录会让人绕开系统私下处理（G1 的反面）。〕

### 3.4 漏斗目标（✅ 定稿，IQ-16 SG-2 批准，2026-10-10）

| 步骤 | 转化率线 | 理由 |
|---|---|---|
