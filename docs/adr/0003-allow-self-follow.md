# 允许自我授权：任何可见者都可把自己加为关注人（附一道前置校验）

权限草案 §6 原写「**禁止自我授权**：用户不得自行往 `*_staff` 加自己（否则可枚举案号自取权限）」。2026-10-12 裁定**撤销这条禁令**：关注人仍是**参与者**（进 L2 可见性、可写节点与评论，§6 其余各条不变），但"我关注"由用户自己一键完成——界面形态即关注按钮组的左段（眼睛）。

理由是用户口径："**查看权限已经决定谁能看、谁不能看；关注只是可以知晓该事项的最新动态（因为会通知）**"。注意这句话在原禁令下并不成立——不设门槛的自我关注就是自取读写。所以撤销禁令的同时**保留那道门槛**：写 `*_staff.follower` 之前，必须校验**操作者现在就能看见这条记录**。加上它之后，"自取权限"不成立（看不见的记录关注不了）；**去掉它等于放开整个 §6 的风控，那是另一次改判，不在本裁定内**。

## Consequences

- 眼睛（我关注）与「n 人关注」（被授予的关注人）是**同一张表的两面**：我点一下，我就出现在名单里、计数 +1（形态照飞书文档的关注控件：眼睛切换自己、右侧 `n 人关注 ▾` 开菜单）。
- **自我关注不受"谁能加/删参与人"的约束**（经办人/L1/创建人那条是给"给别人加"用的）；它只受上面那道可见性校验约束。
- 通知口径不变：关注人只收预置规则 2/8（状态变更、新评论），不是全量推送。
- 移除参与人的连带规则不变：移除 `follower` 时连带删其 `user_watch(follow)` 行（§6:182）；用户自己取消关注 = 删自己那一行。
- 权限草案 §6 两处措辞要改：①"禁止自我授权"那条作废，注明由本 ADR 取代并保留可见性校验；②"谁能加/删参与人 = 仅 owner 与 L1"仍是规则，但性质从**安全边界**降为**产品规则**（它不再防谁，只决定谁有名单管理权）。
