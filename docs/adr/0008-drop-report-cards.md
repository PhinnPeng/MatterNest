# 报表两卡删除：一期不做报表，列表页回到「筛选 + 表格」

2026-10-24 裁定。原 P0-2 的「一期只做 2 张、形态为列表页顶部统计卡」（`ac5c1e1` / MATT-46 落地，
`§4.7` 整节是它的口径）被推翻：两张卡（状态 × 等级总览矩阵、节点到期）在上线一天后判定
**不符合预期**，卡片、`/api/reports`、`services/reports.ts`、`components/report-cards.tsx`
与三个验证脚本整体删除。理由是它们占着列表首屏最大的一块位置，却不回答列表页要回答的问题
（"这一屏有哪些案卷、下一步动哪一条"）—— 要看分布的人已经在用筛选与合计，要看期限的人在用工作台指标带。

## 为什么必须写成裁定，而不是顺手删掉

这条决定已经**被推翻过一次同一个方向的判断**，而且两次都不是因为代码错：

- `efb5468`（2026-10-23）发现 `ReportCards` 从未被挂载，按"规格要求它在列表页顶部"把它接了上去，
  并顺手在工作台加了「案件报表 / 事项报表」两个锚点入口。它做的是**对**的 —— 规格确实这么写。
- `§4.7` 那六条口径（临期按 `remind_days` 分档、未确认时间不进档、与工作台读数的边界…）
  是照着这两张卡写的，读起来会让人以为它们是一期仍需遵守的约束。

所以只删代码不改文档，下一轮复盘会看到"PRD 说要、代码里没有"，然后第三次把它加回来。
本 ADR 与 PRD 的同步修改一起构成那句"不要加回来"。

## 后果

- **删掉的东西**：`/api/reports`、`services/reports.ts`（含 `listFilterOf` 与 `nodeScan`）、
  `components/report-cards.tsx`、`lib/client/api-reports.ts`、`use-list-state.ts` 的 `toReportQuery`、
  `shared/schema/list-query.ts` 的 `REPORT_FILTER_KEYS` / `REPORT_OMITTED_KEYS`、
  工作台两个报表入口、`agent-work/smoke-reports.mjs` / `verify-report-filters.mjs` / `revred-reports.mjs`。
- **保留的东西**：列表页的筛选、合计与导出；工作台指标带（`/api/overview`）—— 它是**另一套口径**
  （"我该先动哪一条"），本来就不与报表共用查询函数，所以删除报表不影响它。
- **列表页的形状回到**：指标带 → 筛选区 → 表格。这是全站五个列表页共用的顺序，不再有例外。
- 将来若真要做报表（第二期），那是**新的一次裁定**：形态、入口、与列表的关系都要重定，
  不要从本仓的 git 历史里把这两张卡的实现捡回来 —— 它们是被判定不符合预期的，不是没做完的。

## 2026-10-24 后续

同日稍晚的 ADR-0009 新增了「报表 · 最近进展」菜单模块。它**不是**把这两张卡捡回来：
统计卡仍按本 ADR 不做；被取代的只有结论里「不进菜单」这一半。
