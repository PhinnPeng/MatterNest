# MatterNest 面向企业当事方，而非律所代理人

PRD 一期全套文档以律所口径写成（律师/客户/承办、按"我方代理谁"建角色）。2026-10 意图对齐时用户澄清：实际场景是**一家企业管理其自身作为当事方卷入的法院诉讼案件**——企业不是替别人打官司的代理人，而是恒定的诉讼参与方。决定：产品域模型从律所代理人口径改判为企业当事方口径，词汇随之全局重命名（见 `GLOSSARY.md`），但 PRD 的功能结构、编号与裁决链不动，仅表述层改。

## Considered Options

- 沿用律所词表、文档里注明"律师泛指经办人"——被否：词会持续把设计拽回律所假设（客户=案源、立场随代理方漂移），这些假设在企业场景里全部为假。
- 按多律所/多租户产品设计——被否（同日裁定 Q3-A）：一期单企业内部工具，云之家单一身份源已锁死单租户；团队/分所隔离维持二期。

## Consequences

- "案件"收窄为**法院内诉讼案件**（裁定 Q5）；风险事项=尚未进入诉讼程序的内部纠纷/事件，转案件触发点=正式立案或被诉（裁定 Q10）。
- 预埋"我方=本企业"的恒定视角（裁定 Q8-A）：我方诉讼地位多为被告、偶尔原告；风险识别、提醒、权限默认站我方立场。
- 外部委托律师只作登记信息、不开登录账号（裁定 Q9-B）：避免撑破"内部三档数据范围"的权限模型。
- M2 的诉讼字段（案由/审级/诉讼地位/标的额/受理机关）**保留有效**——曾疑似作废，被 Q5 救回。
