# 报表作为菜单模块：只做「最近进展」，统计卡仍不做

2026-10-24 裁定。同日 `ADR-0008` 删除了两张列表页统计卡（总览矩阵 / 节点到期），并在结论里写下
「一期不做报表、不建报表页、不进菜单」。本 ADR **只推翻「不进菜单」这一半**：
新增左导航组「报表」，组内一项「最近进展」；统计卡仍按 ADR-0008 不做。

## 为什么不是把两张卡捡回来

两张卡回答的是"分布"（各状态有多少、哪些节点要到期）。用户要的新模块回答的是
**"最近在推进什么"**：一条一条的案卷与最新进展，可筛选、可翻页、可导出。
两者的问题不同，不能用"报表"这个词把它们混成一个决定——恢复卡片会重新占掉列表首屏，
而那正是 ADR-0008 判定它不符合预期的原因。

## 决策

- **入口**：左导航「报表」组，位于业务与系统之间；项「最近进展」→ `/reports/recent-progress`
- **形态**：页面内主从——左列「最近案件 / 最近事项」，右侧对应表格
  （案号/编号、名称、进展内容、类型、时间、经办人）
- **口径**：
  - 排序 `last_progress_at` 倒序；每行取该宿主**最新一条**进展正文
  - 滚动时间窗 7 / 30 / 90 天 / 全部，默认 30 天
  - 可见范围与工作台同一份 `scopedWhere`；归档不计入；必须有进展行
- **入口联动**：工作台「近期活动」右侧「查看更多」进本页（默认最近案件）
- **导出**：导出当前 scope + days 的 CSV（一档，上限 1000 行，审计 `EXPORT`）
- **不做**：统计卡、图表、自定义排序、跨宿主混合导出

## 后果

- 新增 `services/recent-progress.ts`（工作台与报表页共用同一查询）、
  `/api/reports/recent-progress`（含 `/export`）、页面与导航项
- PRD M8 增加本模块的口径；ADR-0008 中「不进菜单」的表述由本 ADR 取代，
  「统计卡不做」仍然有效
- 将来若要做第二张报表，按本 ADR 的形态扩展左列菜单，不要恢复列表页统计卡
