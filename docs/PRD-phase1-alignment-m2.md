## M2 定位（承接根裁定）

案件 = **已进入正式法律程序**（法院诉讼、仲裁、执行）的争议，我方为当事方（Q5+Q25 合并口径：非诉事务一律归风险事项）。它是"案件记录与管理"这条核心价值的载体。与 M1 的语义分叉是刻意的：**事项是台账，案件是战场**——案件有法定硬期限、有裁判机构、有我方恒定立场。

三问速答（模块级）：
- **谁用**：法务经办（主战场）、协办、关注人；业务上报人不直接碰案件。
- **什么时候不用**：还没立案/未收到仲裁通知 → 用风险事项记；纯执行回款跟踪 → 结案后补记，不重开案件。
- **出错代价**：全系统最高——错过举证期/开庭日直接败诉风险（G3 的根）。

## US-M2-1 · 建案（双入口）

**作为法务经办**，我从风险事项转案件，或对突然被诉的案件直接新建。

预期描述（Q13=A + IQ-3）：
- 入口一：事项详情"转案件"（1:N、带入以映射矩阵为准）。
- 入口二：直接新建（被诉/收到仲裁通知），可回填来源事项（可选）。
- 取号 `AJ-YYYYMMDD-XXX`；正式案号 `case_no` 可编辑、非唯一仅提示重复。
- 案件 `owner_id`（经办人）**保持必填**——与事项侧"可空"不对称是故意的：战场必须有负责人，无人盯期限的案件=空转。

功能描述：
- 诉讼字段全保留：案由、`case_type`、`procedure`（含仲裁/执行）、我方诉讼地位、受理机关、标的额（Q5）。
- `litigation_role` 语义钉死为**"我方的诉讼地位"**（原告/被告/第三人/申请人/被申请人）（Q24=B）。

【偏差1】`case_type` 删枚举值"非诉"；"案件"定义从"法院内"扩为"正式法律程序（诉讼+仲裁+执行）"（Q25+Q27 合并）。
【偏差2】`litigation_role` 重命名为**我方诉讼地位**语义；当事人表只放对方/第三人（Q24=B，连带改写 F2-15 与 M3 全部）。

## US-M2-2 · 生命周期（文书生效即结案，执行作尾巴）

**作为法务经办**，判决/调解书生效时我把案件置"已结案"；执行阶段的回款与终本继续在原案补记。

预期描述（Q26=A + Q27 连带）：
- `已登记 → 进行中 → 已结案 → 已归档` 软推荐不变；**已结案不自动归档**（A4 常态）。
- 执行尾巴：结案后节点/费用/评论仍可追加（举证期外的执行款到账、终本裁定），执行完毕人工归档。不引入"执行中"新状态——一期用节点表达。
- 案件状态 `pending` 显示名改**"已登记"**（收案未指派经办前的暂存态，实际很少停留）；`closed` 案件侧保留**"已结案"**——与事项侧"了结"分叉（诉讼词只用于案件）。

【偏差3】状态 seed 显示名：matter `pending`→已登记、`closed`→了结；case `pending`→已登记、`closed` 保留已结案。修订稿 §3.2/基线 4.2 同步。
【偏差4】基线 4.2"从已归档切回其他状态自动撤销归档"维持作废（P0-3 已裁），此处再钉一次：归档终态、仅撤销特权可逆。

## US-M2-3 · 案程节点（保留模板——案件是战场）

**作为法务经办**，案件进入"进行中"时系统按规则 3 自动生成 立案/举证/开庭/判决 四节点，带 `{7,3,1}` 天提醒；我可增删改。

预期描述（Q27=A，与 M1 不对称）：
- 事项砍预设（无固定流程）；案件**保留** P2 模板 + P1 预设双路径——法定硬期限是外部强加的，错过即败诉风险。
- 案件节点支持**时间点与时间段**（开庭=区间，F2-9 不变）；事项节点仅时间点（Q22）。

【偏差5】无——本节是"维持现规格"的确认记录（防 M1 裁定被过度推广到案件侧）。

## US-M2-4 · 记录管理（对称继承 M1）

- 编辑：协办可改主表业务字段；关注只读（P0-6 结案，对称 M1/Q18）。
- 删除：仅软删、无回收站 UI（B8/P1-8 结案）。
- 评论：可编辑带"(已编辑)"（P1-11 结案）。
- 批量：仅低风险动作（改状态/归档/加标签）；不做批量转案件与批量删除（P1-9 结案；案件侧本无批量转）。
- 费用：仅支出（诉讼费/律师费/保全费），企业场景语义天然成立，`approved` 位仍留二期。
- 导出：脱敏/明文两档保留，明文查看记审计（对象=对方当事人个人信息，非"我方客户"，见 M3）。

【偏差6】"承办人"全局改名**经办人**（Q11），M2 全部 F 表述随改。
