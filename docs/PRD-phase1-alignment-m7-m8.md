三问速答（模块级）：
- **谁用**：L1 角色（导入/维护）；其余人被动消费（编号、日志、Tab）。

- **出错代价**：导入脏数据第一屏吓退用户 ⇒ 模板校验与查重联动是导入器的本体。

## US-M7-1 · 批量导入（一期做，P1-4 结案）

**作为全局管理/全局经办（L1）**，我上传 Excel 模板，把企业旧台账里的**风险事项与案件**一次性迁入；当事人随行按名称+证件号哈希查重自动建档或挂接已有档案。

预期描述（Q42=A）：
- 三张模板：事项 / 案件 / 当事人（当事人可独立导，也随事项/案件行内嵌）。
- 导入行一律落 `已登记` 态；`created_by` = 导入操作人；编号照走 FX/AJ 生成器。
- 权限：仅 L1 角色可执行（与 Q40 捞取面一致）；导入本身写一条汇总日志。
- 校验失败行**整批拒收还是逐行跳过**：逐行跳过 + 错误报告下载（导入的是历史烂账，全有全无会永远导不进去）。
- 原型缺口 P14 由此升为**必须出原型**（开工前置）。

【偏差1】F7-4 从 ❓P1-4 结案为上述口径；§6.2 上线筹备加"导入演练"一项。

## US-M7-3 · 编号 / 附件 / Tab 框架（无改判，确认维持）

- F7-1 编号：`FX/AJ-` 前缀与业务时区日界不变；企业口径下前缀语义注记（FX=风险事项、AJ=案件）。
- F7-3 附件签名：预签名 PUT + 60s 下载不变；企业无额外合规要求压在此处。
- F7-6 Tab 框架：**案件侧不变**（基本信息/进展/节点/费用/评论/附件/日志/提醒）。**事项侧改为双栏制**（2026-10-11 P5 原型裁定，原「Tab 集合调整为六项、评论前置」作废）：
  · **左栏＝工作面**：事项节点在上（手动、可空、无预设），**处置记录在下并撑满剩余高度**——处置记录即评论沟通（Q14），它是事项的主交互面，放在底部保证一进来就在视线里且可滚动到底。
  · **右栏＝档案**：Tab 只有【基本事实 / 活动日志】两个，纯查阅用。
  · 原 Tab 里的**附件**并入「基本事实」Tab 末节；**提醒**挂在节点上（节点自带提醒天数），不再单列 Tab——事项无预设节点时提醒本就无从谈起。
  · 事项无预设节点、节点仅时间点这两条裁定不变（IQ-5）；本次只改**摆放位置**，不改语义。
  · 全局：用户信息从顶栏移到主菜单底部，标题栏动作收敛为「编辑 / 变更处理人 / 更多（转案件、复制、加关注人、归档、删除）」。
- F7-7 自定义字段/列：维持不做（清单#14）；列显隐持久化仍挂 P1-21 待拍（技术产品边界，非本轮）。

【偏差3】F7-6 事项详情布局改为双栏制（见上）。
