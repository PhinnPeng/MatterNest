## 候选 1 · 判据脚本把「本机事实」写死了

**Severity：高** —— ✅ 已落地 ① ②；③ 需要一次裁定。

本仓的「完成判据」就是 `agent-work/` 下的脚本（MATT-1 目的地第 2 条：
每票的判据要能被**别人独立跑一遍**复现）。而 `agent-work/` 恰好是**五道门禁一道都不读它**的地方：

```
eslint.config.mjs   ignores: agent-work/**        ⇒ 不解析、不查 no-unused-vars
.prettierignore     agent-work/                   ⇒ 不格式化
anchors:check       只从 revred-*.mjs 抽 needle 字面量
tools/run-smokes.mjs 只发现 smoke-*.mjs           ⇒ 22 个 probe-*.mjs 零运行者
lint-guard          源码断言只 walk src/**
```

于是「脚本起不来」是**静默**的 —— 本轮实测两种形态，都是真事：

```
① chromium 版本漂移：写死 1224，本机只有 1248（`npx playwright install` 决定目录名）
② playwright 模块根写死：绑在 nvm 的**node 版本目录**上（nvm/v22.22.2），
   而 playwright 只有一份全局安装、不在 package.json ⇒ node 一升级同样全灭
```

**为什么门禁抓不到**：见上表。判据脚本本身没有任何东西读它的语义。

**已落地**：

```
① 本机事实收敛到 `agent-work/_chrome.mjs`
   · pickChrome()     取 ms-playwright 下**版本号最大**的 chromium（不再写死版本；
                      也不再回落到一个写死的用户名目录 —— LOCALAPPDATA 缺失就抛错）
   · playwrightRoot() 从 `process.execPath` 推 <node>/node_modules/playwright
                      —— 换 node 版本它跟着走，这正是写死 nvm/v22.22.2 做不到的
   · 两个函数**抛错**，不返回 null：null 传下去只会变成
     `chromium.launch({ executablePath: null })` 那种「报的是别的功能的错」的现场
   11 个探针改成 `createRequire(playwrightRoot())`；probe-mention-render 的
   `if (!CHROME)` 守卫随之成了死代码（pickChrome 自己抛错），删掉。
   实测：真起浏览器，version 156.0.8078.4。

② 门禁⑪ 判据脚本可移植（`tools/lint-guard/judge-portability.mjs`），三条断言：
   ① 语法：81 个入库 .mjs 全部 `node --check` 通过（并发 6，整个 lint-guard 4.1s）
   ② 相对 import 的目标必须**已入库**（`git ls-files` 判定 —— 候选 2 的同一件事）
   ③ **引号形态**的机器绝对路径一律不许出现（注释/说明文字里写路径不算：
      `_chrome.mjs` 的文件头就写着那条失效过的路径，好让下一个人知道为什么不能写死）
   每条断言带反假通过哨兵：扫到 0 个文件、解析到 0 条 import ⇒ 直接报红，
   不给「假通过」留口子。
   反向红实测 4 条：机器路径 / 未入库 import / 语法错 —— 三条都拦下；
   「注释里的路径」希望不报 —— 实测不报。
```

**③ 待裁定 · 让 CI 真跑一个探针**（Severity 高）：

现在 22 个探针零运行者，「跑得起来」永远只有人眼这一次。门禁⑪ 只证明
「是合法 JS、依赖都在库里、没写死本机路径」，不证明它真能跑。
障碍具体：CI 在 Ubuntu，而 `pickChrome()` 是 Windows 形状（`LOCALAPPDATA` +
`chrome-win64`），要先解决「Linux 上 playwright 从哪来、装在哪」。
这与候选 4 是同一件事的两面。

⚠ **诚实的边界**：门禁⑪ 抓不到「路径取法对了但依赖没装」；模板串形态的机器路径
不在范围内（本仓判据脚本写路径都是普通字符串，实测）；恒假断言抓不到。

## 候选 2 · `agent-work/` 白名单制的入库坑

**Severity：中** —— ✅ 已落地。

`agent-work/` 整体忽略 + 逐个 `!` 放行（否则 154 个文件里的会话杂记、截图、
60+ 个 `_*` 草稿会一起入库）。

```
后果：新增**共用助手** `_chrome.mjs` 不会被提交 —— 11 个探针 import 它，
      本地跑得好好的，别人 clone 下来直接「import 一个不存在的文件」。
      「本地全绿、别人全红」是本仓最容易接受不了的那种状态。
另：`.gitignore` 的注释还写着「例外只开三类」，实际已经 5 类通配 + 3 个单文件。
```

**已落地**：

```
① 门禁⑪ 第 ② 条（相对 import 的目标必须已入库）—— 这是唯一能自动发现它的东西
② `.gitignore` 注释按实际改写，并明说「新增共用助手是这里**唯一一步手工操作**」，
   指向门禁⑪ 第 ② 条
```

**为什么不直接类级放行 `!agent-work/_*.mjs`**：目录里有 60+ 个 `_*` 草稿文件，
类级放行会把它们全部放进来。白名单制的代价就是「每个新助手一行手工」，
所以那一步得有门禁兜住。

## 候选 3 · 缺口登记簿的「等票」没有到期检查

**Severity：中** —— 需要一次裁定。

B1 的事实：`src/app/lib/server/db/enum-check.spec.ts` 的 `AUDIT_WITHOUT_WRITESITE`
里 5 条理由写着「等 MATT-61 / MATT-73 / MATT-74」，而三张票**都已 Done**，
门禁仍然绿 —— 因为**写入点确实还不存在**（#61 交付的是规则 4 的扫描器，
不是自动化规则执行器；方向也错了，注释把 #61 说成了执行器）。
所以这不是「忘记改文字」，是**没有任何东西会去复查「理由里引用的票是否已经 Done」**。

登记簿的现行三态纪律是「真缺口 / 等票 / 有写入点」，而**「等票」这一态天然会过期**：
票做到了，理由就旧了，而门禁只看「写入点存不存在」，不看「等的票到没到」。

**建议**（本轮只改判文字，未加门禁）：

```
① 「等票」的理由改成**可判定的固定形态**（如 `等 MATT-73`），
   门禁对每条「等票」条目去查 Paca 快照里该票的状态，Done 了就报「理由过期」
② 反方向也要有：写入点真补上就必须**删条目**（现行纪律），否则登记簿退化成永久白名单
```

`tools/board-drift.mjs` 已经有「Paca 快照 ✕ git」的纯函数分级器，
这条天然是它的第三段（同一种输入、同一种输出）。**要不要并入它是一次裁定。**

## 候选 5 · 环境侧：shell 单行里塞不进中文与正则

**Severity：低** —— 无法仓内落地，只能是纪律。

本轮**我自己踩了一次**：`node -e "…|…中文…"` 在 PowerShell 下被解析器打断
（`|`、引号、非 ASCII 三样凑在一起）。同一轮里，改成「写一个 `.mjs` 文件再跑」
全部顺利 —— 包括那三个批改脚本（改 11 个探针、改 import、反向红）。

可落地的只有纪律，且本轮已经有一处**物质化**的证据：所有一次性脚本都落在
`%TEMP%\opencode\*.mjs`，跑完可以复看、可以改、可以再跑。

顺带一条已知事实：**shell 输出中文会乱码**（含自己写的字面量）。
所以判据脚本的结论要**以退出码与 `ok(...)` 计数为准**，
不要靠读中文输出 —— 门禁⑪ 的三条断言也遵守这一点（报数与文件名，不靠人读句子）。
