## M5 定位（承接根裁定）

企业口径下"状态配置驱动"的原始理由（各所叫法不同）弱化，但配置面并未失去价值：它变成**"把预置规则调成本司口味 + 字典随公司实际改名"**的适配层，而非自动化平台。IQ-2"其余皆附加"在此落地为一次明确砍量：通用自建规则出局。

三问速答（模块级）：
- **谁用**：sys_admin/full_admin（配置与启停）；规则的消费端是全员（提醒到达）。
- **什么时候不用**：一期没人搭新规则——预置规则（裁定时 8 条，IQ-16 增至 9）的启停改参就是全部日常运维。
- **出错代价**：§2.1 原话"规则放开成通用引擎会失控"；配置页的代价反而在"停用被引用状态"这类守护逻辑（F5-2 保留）。

## US-M5-1 · 规则管理收窄为"预置规则运维"

**作为管理员**，我看到 9 条预置规则，可启用/停用、调参数（提前天数、收件人、天数阈值）；**不能自建新规则**。

预期描述（Q36=A）：
- 保留：F5-7 列表与详情、F5-10 预置管理（`is_system`：可调参可停用，不可删不可改 trigger）、F5-11 执行记录。
- 移出：F5-8 新建规则、F5-9 自建规则冲突处理——**列二期**（§3.5 的"or/聚合规则引擎"本就是二期候选，一并等）。
- 引擎侧连带变薄：字段/动作白名单配置器、scope_key 冲突检测 UI 一期不做；`automation_rule` 表结构照旧（二期恢复自建入口时无迁移债），但一期 seed 后表内只有 8 条 `is_system=true`。
- 同域唯一约束与"状态被停用引用阻止"（F5-2）保留——它们守护的是预置规则间与状态字典的一致性，不因砍自建而失效。

【偏差1】F5-8/F5-9 一期移出（PRD 现列 ✅ 在第一期）；修订稿 §2.5"可新建同结构规则"划掉，标二期。

【偏差2】规则 3（进入进行中创建节点）`host_type` 从 `all` 收窄为 **`matter`（仅案件）**——事项无预设节点（M1/Q14）。
【偏差3】规则 4（长期未更新提醒）`host_type` 从 `all` 收窄为 **`matter`（仅案件）**（Q37=B：观察型事项 30 天一催是噪音，案件的静默才是危险信号）。
【偏差4】预置节点类型 seed：核查/反馈类型保留但 `preset_on_create` 对 `risk_matter` 全 false（M1/Q14）；`risk_matter_default` 模板（受理/核查/反馈）一期不挂任何自动触发，仅作手动添加时的可选类型池。
【偏差5】状态 seed 显示名同步 M1/M2 重命名：pending→已登记（双宿主）、事项 closed→了结、案件 closed 保留已结案；code 不变（`code` 不可改是既有契约，改的只是 name 列）。

## US-M5-2 · 提醒配置=改默认提前天数（F5-14 收窄）

**作为管理员**，我能改节点提醒的默认提前天数（如 {7,3,1}→{10,5,1}）；**超期升级与多级提醒一期不做**。

预期描述（Q36 连带 + Q15 连带）：
- 超期升级依赖"升级到谁"——企业里升级对象若是责任部门负责人，而 Q15 已暂缓部门维度 ⇒ 无落点，一期出局。
- 多级提醒与 `remind_days integer[]` 的表达能力重叠，一期不开后台入口。

【偏差6】F5-14 从 ❓ 结案为"一期仅默认提前天数可配；超期升级/多级不做"（P1-6 的一部分由此关闭）。

## US-M5-3 · 配置后台形态（Q38 用户亲拍）

**作为管理员**，每个配置项是**独立功能页**：状态配置页 / 节点类型配置页 / 风险等级配置页 / 标签配置页 / 费用项目配置页，各页独立维护、独立入口；**不做合并"字典页"**。

预期描述：
- 与基线 7.1–7.8 的原生分页结构一致；菜单树 §4.3 的配置分组按此逐页列。
- 移出项：**存储配置（F5-13）一期不做后台页**——上传白名单/大小/预览开关走环境配置（一期单所自用，参数极少改）；**通知模板管理（F5-12）一期只 seed 无管理页**（文案 B5 未定稿 + 模板改动本质是发版动作）。

【偏差7】F5-13 一期移出（列二期）；F5-12 维持"只 seed"但明确"管理入口列二期"——P1-6 结案。
