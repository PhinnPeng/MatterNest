# M1 风险事项 · 意图对齐产出（US + 预期描述 + 功能描述）

> 生成于 2026-10-10 对齐轮。判据=三问（谁用/什么时候不用/出错代价）；口径=企业当事方（见 `docs/adr/0001`）。
> 本文是"PRD 草稿被对齐改判"的落地件。每节末尾的【偏差】= 相对现有 PRD/基线/修订稿的改动点，回写主文档时逐条处理。

## M1 定位（承接根裁定）

风险事项 = **企业尚未进入诉讼程序、但已识别的内部纠纷或事件**（合同违约苗头、劳动争议、供应商纠纷、监管/处罚前兆、安全事故等）。它是"事项记录与管理"这条核心价值（IQ-2）的载体，是转案件的上游之一，但**不是案件的前置闸门**（IQ-3/Q13）。

三问速答（模块级）：
- **谁用**：业务部门上报人（登记）、法务经办/协办（处置与转案件）、关注人（知悉）。
- **什么时候不用**：事件已经在法院立案 → 直接建案件，不必先编事项；纯台账/备忘性质 → 系统不鼓励。
- **出错代价**：漏记一条风险 = 错过时效或未识别的诉讼敞口（G3）；这正是本模块存在的理由。

## US-M1-1 · 登记（可选填处理人与关注人）

**作为业务上报人**，我登记一条风险事项并填写基本信息，提交后它进入"已登记"态；登记表单上我**可选填**处理人（经办）与关注人——十人企业里报事的人多半知道该给谁。

预期描述（Q12=B + V2 修正，2026-10-10）：
- 上报即落 `已登记`，系统取号 `FX-YYYYMMDD-XXX`。
- 无强制"待受理/受理"流程闸门（Q17）。事项创建后不阻塞在某一角色手里。
- 上报人可编辑自己创建的事项；处理人一经设置，编辑权归经办与协办（Q18-A，去掉"待受理期"限制）。
- owner（处理人）允许为空——空表示未指派，落"具备可见权限者即可见"（Q23=A）。
- 处理人空置时，持 L1 的角色把处理人改成自己 = 一次普通的**变更处理人**字段编辑（护栏 1 既有动作，非独立流程、不单设审计项）。

功能描述：
- 必填：名称、类型、风险等级、描述、发现日期；**选填：处理人、关注人**。经办人 `owner_id` **改为可空**（原必填）。
- 状态初始值 `已登记`（原"待受理"改名，去流程暗示）。

【偏差1】基线 3.1 `owner_id 必填=是` → 改可空。
【偏差2】状态 `pending` 显示名 "待受理" → "已登记"；`closed` 事项侧显示名 "已结案" → "了结"（"结案"是诉讼词，企业事项侧不用）。改 status_config seed 与 §3.2 文案。

## US-M1-2 · 处置靠评论，节点按需

**作为法务经办**，我在事项上以评论记录核查与反馈；确有期限时才手动加节点。

预期描述（Q14=B + Q16=B）：
- 事项**不预设任何节点**（撤销"默认 3 节点"）。核查/反馈作为**评论**功能承载，可 @ 提及、回复。
- 节点降级为**可选、手动增删**：仅在"有硬期限"（如诉讼时效、答复期）时加。
- 事项侧节点**只给时间点**，不支持时间段（Q22=A；区间仅案件节点用）。

功能描述：
- 评论可编辑，显示"(已编辑)"标记，改动写 `COMMENT_UPDATED` 日志（Q21=A）。
- `risk_matter_node` 表保留但去掉 preset；F1-8/F1-9/F1-22/F1-16 全部挂在"手动节点"下继续有效。

【偏差3】基线 3.3"默认 3 节点：风险评估/处置执行/化解确认" → 作废，改为无预设、可手动加。`node_type_config.preset_on_create` 对 `host_type=risk_matter` 全部置 false。

## US-M1-3 · 转案件（入口之一，非唯一）

**作为法务经办**，当风险正式立案或被诉，我从事项详情页点"转案件"生成诉讼案件；案件也可不经事项、直接新建。

预期描述（IQ-3 + Q13=A）：
- 触发点 = 正式立案/被诉那一刻，不是"风险升级"。
- 事项→案件走既有映射矩阵（1:N、单事务+outbox、带入规则以映射为准）。
- **案件独立新建入口**必须存在（被诉场景常无对应事项）；转案件徽标逻辑不变。

【偏差4】§3.3 核心路径图"登记→…→转案件→归档"需加注："转案件是建案入口之一，非唯一；被诉可直接建案件"。

## US-M1-4 · 记录管理（列表/编辑/归档/删除/批量）

- 编辑：协办与经办可改主表业务字段（标题/描述/金额/等级），关注只读（Q18=A，P0-6 结案）。
- 归档：与案件同构，`archived` 终态、仅撤销特权可逆（P0-3 不变）。
- 删除：**仅软删、无回收站 UI**，full_admin 可在库内恢复；普通用户不可见已删行（Q19=A，B8/P1-8 结案）。
- 批量：**一期仅低风险动作**——批量改状态/批量归档/批量加标签；**不做**批量转案件、批量删除（Q20=A，P1-9 结案）。
- 可见：owner 空置的事项对"具备可见权限者"默认可见，靠列表筛"经办人=空"捞新，无专门待指派入口（Q23=A）。

【偏差5】基线 3.1 `source` 枚举含"客户投诉""律师函"律所残留词 → 企业口径改名：客户投诉→对外纠纷/投诉；律师函保留但语义标注为"收到对方当事人律师函"。改枚举 E 系列与基线文案（随 M3 当事人"对方当事人"命名一并核对）。
